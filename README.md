# Solar System Data Analysis

An interactive web page backed by a Python analysis layer. Physical properties
like density, surface gravity and escape velocity are **calculated** from each
planet's mass and radius rather than looked up.

## Files

| File | Layer | What it does |
|---|---|---|
| `planets_data.py` | Data | Raw measurements only (mass in kg, radius in km, distance in AU, temperature, orbital period, moons). No derived values, no presentation. |
| `analysis.py` | Logic | Calculates density, surface gravity, escape velocity and classification. Also computes summary statistics, rankings, two-planet comparisons and the distance-vs-temperature correlation. Imports no web code, so it can be tested on its own. |
| `app.py` | API | Thin Flask wrapper. Every route calls one `analysis.py` function and returns JSON. Also serves the front-end files. |
| `index.html` | View | Page structure. |
| `fp.css` | View | Styling. |
| `fp.js` | View | Fetches from the API, builds the dropdown, planet card, sortable table and the finding. |

## How to run it

**Option 1 — full stack (recommended for the demo)**

```bash
pip install flask
python3 app.py
```

Then open <http://127.0.0.1:5000/>. Flask serves the page *and* the API from the
same address, so there is nothing else to start. The badge under the title will
read **"Live data from the Flask API"**.

**Option 2 — just the page**

Double-click `index.html`. The page tries the API first, and when no server
answers it falls back to a copy of `analysis.py`'s output that is embedded in
`fp.js`. Everything still works; the badge reads **"Offline mode"**.

**Option 3 — the analysis on its own, no browser**

```bash
python3 analysis.py
```

Prints a full text report: derived properties, extremes, the correlation and an
Earth-vs-Mars comparison.

## API endpoints

| Endpoint | Returns |
|---|---|
| `GET /api` | Self-describing list of endpoints |
| `GET /api/planets` | All eight planets with derived properties |
| `GET /api/planets/<name>` | One planet, case-insensitive (e.g. `/api/planets/mars`) |
| `GET /api/analysis/summary` | Min / max / mean for each metric |
| `GET /api/analysis/rankings` | Planets ranked by five metrics |
| `GET /api/analysis/correlation` | Distance-vs-temperature relationship |
| `GET /api/compare?a=Earth&b=Mars` | Side-by-side comparison with ratios |

## What the page shows

- **Planet picker** — choose any planet for its image, classification and a full
  stat table. Values in bold are the ones `analysis.py` calculated.
- **All eight planets** — sortable on any column. Click a row to jump the
  dropdown to that planet.
- **The finding** — Pearson r between distance from the Sun and average
  temperature is **-0.634**, a moderate negative relationship. Venus breaks the
  trend: it is hotter than Mercury despite being farther out, because its thick
  carbon-dioxide atmosphere traps heat. Distance alone does not decide
  temperature.

## Design notes

The three layers are kept strictly separate:

- `planets_data.py` holds only raw measurements, so nothing derived can drift
  out of sync with the numbers it came from.
- `analysis.py` takes plain data and returns plain data — no Flask imports — so
  the logic is testable and reusable outside the web app.
- Images and descriptions live in `fp.js`, not in the data file, because they
  are presentation and the analysis never needs them.

The dropdown and the table headings are both generated from the data at runtime,
so adding a ninth body to `planets_data.py` would flow through the API, the
dropdown, the table and the statistics without touching the HTML.

The offline copy inside `fp.js` was generated by running `analysis.py`, so both
data paths display identical numbers.

## Data source

NASA planetary fact sheets (approximate mean values). Moon counts and gas-giant
cloud-top temperatures vary by source and over time.
